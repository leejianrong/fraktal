# Spike: Infinigen as an asset generator (FRK-52)

Verdict: **defer.** Nothing here rules it out, but the trial the card asked for (generate assets
headless, time them, compare with the CC0 baseline) was not run, so there is no cost or realism
number. This note is from Infinigen's own docs and repository metadata, read on 2026-11-05.

## What I could not do

The trial needs a clone of `princeton-vl/infinigen` and a `pip install` of it (and its pinned
dependencies) into a scratch virtualenv. The session's permission check refused that command, so I
did not run it and did not look for a way around it. If you want the trial, say so and approve the
install; it is a half-hour job (see "Trial plan").

## What the docs say

- **Licence of the code:** BSD-3-Clause (Princeton University, GitHub licence metadata and the
  LICENSE file). The README adds that newer versions include some procedural code taken from the
  internet under CC0, marked in code comments. Not read: any statement about the licence of what it
  generates, or of any bundled data. That has to be checked before an asset enters the manifest.
- **Install:** Python 3.11 only, and it pins `bpy==4.2.0` and `numpy<2`. Our Blender path runs bpy
  5.0.1, so Infinigen needs its own virtualenv or pod, exactly like our bpy venv. The "minimal
  install" (`INFINIGEN_MINIMAL_INSTALL=True`) skips the terrain and OpenGL builds and is enough
  for objects and materials; it is listed as working on Linux x86_64 and "experimental" on WSL2.
  The full install needs a C++ toolchain and system graphics libraries.
- **Headless single assets:** `python -m infinigen_examples.generate_individual_assets -f <Factory>
  -n N --save_blend` writes a .blend per asset, and `--export obj|usdc|...` bakes meshes with
  textures. Factories cover nature objects (cacti, corals, clouds and more, from a list in
  `tests/infinigen/assets/list_nature_meshes.txt`) and materials.
- **Maintenance:** last push 2026-11-02, latest release 2.0.0a3 (an alpha), about 7,400 stars.

## Fit with what we need

Our biggest visible gaps in the 3D path are trees (ellipsoid crowns), ground material and
rocks or scrub. Infinigen's nature generators are aimed at those, so it is relevant to
the tropical biomes more than to the dense_urban typology work. It does not replace the building
grammar. Open questions that only a trial answers: whether it has tropical trees and palms of the
right look, how long one asset takes on a CPU pod, how heavy the meshes are for 1,000 trees a tile,
and whether baked meshes can come into our scene as data (they would need a new scene file kind;
the current contract has only footprints, ground and the building mesh arrays).

## Licence gate before use (ADR-0010 decision 5)

An Infinigen asset can enter `assets/` only if: the BSD-3 notice is carried for any copied code
(not for generated outputs, if outputs are unencumbered); every bundled texture or HDRI used is CC0
or generated by us; and the manifest row records the Infinigen commit, the factory name, and the
seed, so the asset can be regenerated. Generated outputs would be `owned` only if the above holds;
otherwise they stay out.

## Trial plan (about 30 minutes, once approved)

1. In a scratch directory, `git clone --depth 1`, then minimal install into a Python 3.11 venv.
2. Generate five factories (a tree, a palm if there is one, a bush, a rock, a ground material) with
   `-n 3`, timing each, and note mesh size.
3. Bake one to OBJ, load it in our Blender scene, and look at it from a nadir and an oblique camera
   next to the current ellipsoid trees.
4. Write the result here as keep, defer or drop, with times and a picture.
